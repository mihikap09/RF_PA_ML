# Reproducibility

## Declaration of reproducibility

We declare that every result, table and figure reported for this project was
produced by the code in this repository, from the dataset committed in
`datasets/`, and can be regenerated by following the steps in `README.md`
section 3.

Specifically:

- **No result was obtained by hand, by a notebook that is not in this
  repository, or from an earlier version of the code.** Every number in the
  report traces to a file under `results/`, written by one of the committed
  scripts.
- **Test data was used once, to report.** Memory depth, hidden width and random
  seed were all selected on the validation split. The test split was never used
  for any modelling decision.
- **All models are scored on identical samples.** Because models with different
  memory depths cannot predict the first samples of a split, the same leading
  samples are discarded for every model before any metric is computed. This is
  enforced in code, not by convention.
- **No cross-split leakage.** Past-sample windows are constructed inside each
  split and never span a split boundary.
- **Randomness is seeded.** `--seed` fixes the PyTorch and NumPy seeds; the
  value used is encoded in every output filename. Neural results in the report
  are given as mean ± standard deviation across three seeds.
- **The polynomial baselines are deterministic.** Their coefficients are solved
  in closed form by least squares, so they reproduce bit-for-bit on any machine.

### Known sources of variation

We state these rather than claim exact reproducibility where it does not hold:

1. **Neural results vary with seed** by up to ~0.13 dB NMSE. Reported values are
   the mean over three seeds, with the spread given alongside.
2. **BLAS and PyTorch versions** can change floating-point summation order.
   Differences appear beyond roughly the twelfth significant figure and do not
   affect any reported digit.
3. **`--threads` and `--device`** change execution order but not the reported
   metrics beyond the tolerance above.

### Limitation on the DPD results

The dataset is a fixed recording, so a predistorted signal cannot be passed
through the physical amplifier. **All linearisation results are measured against
the learned PA surrogate, not hardware.** This is stated in the report and is
not a claim of measured hardware improvement.

## Artifact index

Everything a reader needs to verify the report without re-running anything.

### Checkpoints — `models/`

| File | Size | What it is |
|---|---|---|
| `dpd_pa5_dpd5_h32_s0_pe200_e100_sp0_g1_pk1_b2048_lr0.001.pt` | 19 KB | Main DPD checkpoint: PA depth 5, DPD depth 5, 32 hidden, seed 0, 200 PA epochs, 100 DPD epochs |
| `dpd_pa5_dpd5_h32_s0_pe20_e20_sp0_g1_pk1_b2048_lr0.001.pt` | 19 KB | Short-run checkpoint used for the ablation |

Both checkpoints are committed directly. They are 19 KB each, so no external
hosting was needed and no Hugging Face link is required. Filenames encode the
full configuration: `pa<depth>_dpd<depth>_h<hidden>_s<seed>_pe<PA epochs>_e<DPD
epochs>_sp<spectral weight>_g<target scale>_pk<peak weight>_b<block>_lr<rate>`.
